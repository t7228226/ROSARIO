# 內部更新紀錄

此文件只供維護與測試追蹤，不會顯示在網站介面。

## 2026-08-08-002

- 修正登入自動送出：只有密碼欄本身被瀏覽器自動填入才可自動登入；使用者鍵盤輸入或貼上時不再誤送出。

## 2026-08-08-001

- 當班全勤摘要拆分為可作業人力、已配置站點與未配置備援，避免將未配置備援誤認為缺員。

## 2026-08-02-006

- 第一天、第二天的全勤基準改為本班與對班支援人力合併計算。
- 最佳指派、指定缺勤與預防性壓力測試統一先配置支援人力，再由本班補位。
- 基準摘要新增支援已配置、本班補位與本班可備援人數，並以藍色標籤標示支援指派。
- 第一天、第二天的預防補訓只推薦本班人力，避免把短期支援人力當作本班長期補強對象。

## 2026-08-02-005

- 修正第一天、第二天的缺口分析誤用輪休需求。
- 日別現在只決定本班與支援班出勤名單，正常工作時段一律使用最低需求。
- 輪休需求保留為獨立計算值，不再由日別選項自動套用。
- 缺口明細的需求欄固定標示為最低需求。

## 2026-08-02-004

- 缺口分析進入頁面即顯示全勤基準，不需先指定缺勤人員。
- 新增可自訂 1～5 人的預防性缺勤壓力測試。
- 小型組合完整排列；組合過大時採固定抽樣並在結果標示。
- 每個缺勤情境皆使用全站最大匹配重新排列，禁止同一人重複覆蓋不同站點。
- 顯示各缺勤人數的基準維持率、最小關鍵缺勤組合與風險站點。
- 補訓建議改以實際降低缺口與解除缺勤風險為主，認證數少僅作同分排序。
- 壓力測試移至背景執行，避免大量排列時凍結操作畫面。
- 保留指定缺勤、幹部支援與自訂補訓，供每日狀況進一步模擬。

## 2026-08-02-003

- 新增可靠寫入操作編號 `operationId`。
- GAS 使用 Script Properties 保存 24 小時內的操作狀態與結果。
- 相同操作編號再次送達時，直接回傳既有結果，不重複寫入。
- 新增 `operationStatus` 查詢，供前端在逾時後確認寫入結果。
- 前端同內容的同時請求會共用同一個 Promise，阻擋快速重複點擊。
- 未確認結果會暫存在 `sessionStorage`，再次操作時沿用原操作編號。
- 移除每次寫入前的前端雙重版本查詢，改由 GAS 同請求驗證版本。
- 所有寫入動作統一使用文件鎖，新增人員不再自行建立巢狀鎖。
- 增加 GAS 防重複寫入自動測試與契約檢查。
- 支援舊 `v2` 名稱與新短版本名稱的正確新舊比較。
- 正式部署後停止舊版寫入，避免舊頁面繞過可靠寫入流程。
